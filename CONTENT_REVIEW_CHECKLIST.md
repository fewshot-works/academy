# Content Review Checklist

Used to vet any new content — blog posts, chapters, labs — before it's considered ready to
publish or merge. Apply the full list to chapters/labs. Blog posts only need the items marked
**(blog)**; skip the rest unless the post links to or embeds a lab.

1. **(blog) Accuracy — claims & data.** Fact-check every factual or statistical claim.
2. **(blog) Accuracy — historical context & trivia.** Verify any historical facts, trivia, or
   "did you know" asides.
3. **Lab accuracy.** Every lab must run end-to-end as written; README instructions must be
   complete and correct.
4. **(blog) Language clarity.** Sentences read clearly and are easily understandable — no
   undefined jargon.
5. **(blog) Paragraph/sentence flow & formatting.** Paragraphs end on a logical thought; fonts,
   styling, and emphasis (bold, italics, callouts) are used correctly and purposefully.
6. **(blog) Tip/trivia emoji marker.** Tips, trivia, or "did you know" call-outs use an obvious
   visual marker (e.g. 💡) so they stand out from regular text.
7. **(blog) Tell-tell-tell format.** Recap what's covered → cover it → recap what was covered.
8. **Quiz answer accuracy.** Every "Check Your Knowledge" quiz answer is actually correct.
9. **Checkpoint vs. quiz overlap.** If the Checkpoint recap already answers a question repeated
   in "Check Your Knowledge," that quiz question is moot — flag it and replace it.
10. **Cross-platform lab commands.** Every lab command runs as written on macOS, Linux, and
    Windows terminal (not WSL) — no OS-specific syntax without a noted alternative.
11. **(blog) ADHD/short-attention-span friendly.** Short paragraphs, frequent breaks, no dense
    unbroken scrolls of text.
12. **Lab UI where applicable.** Labs should have a visible UI attached wherever it makes sense,
    so the learner sees the work happening instead of reading raw terminal output alone.
